# The host container, the app, navigation and theme

**Status (2026-09-19, codec 1, Android):** detection, the handshake, `createApp`, theme and chat
work, and so does `navigateTo` to an outside URL. No host API tells you the app's version.

## Detect the host, then handshake

```ts
import { isInsideContainer } from "@parity/product-sdk-host";
// Outside the app nobody answers this message round-trip, so it needs a deadline.
const inHost = await Promise.race([isInsideContainer(), new Promise<boolean>((r) => setTimeout(() => r(false), 1500))]);
```

The handshake is where a **wire codec mismatch** shows up: every host call after it hangs. Pin the
SDK to the codec the app speaks ([pitfalls/wire-codec.md](../pitfalls/wire-codec.md)).

## Which app build am I on?

**You can't tell.** No truapi namespace has a version call (`system` offers `handshake`,
`featureSupported` and `navigateTo`). The user agent's Chromium version is the Android **system
WebView**, updated through the Play Store separately from the Polkadot app, so it doesn't identify
the app either. This repository keys runs by date, wire codec, SDK and OS instead. If you can read
the version off the phone (Settings → About), put it in `runtime.appVersion`.

## How big one host call can be

A 4 MiB value crosses the bridge both ways (host local storage, 2026-09-19 12:55), and 16 MiB is
refused with an error. Writing 8 MiB killed the page. Treat **4 MiB as the ceiling for any single
host call.**

## Calling the host a lot

200 host calls fired at once all answered correctly, in 1.7 s (10 took 175 ms, 50 took 828 ms).
There's no need to serialise calls by hand. (2026-09-19)

## Getting a new build onto the phone

Close the product, then **close the Polkadot app itself**, then open the product again. Closing only
the product kept showing the previous build (almanac). Show a build id in your footer so you can
tell which build is running.

## navigateTo

`navigateTo(url)` asks the host to open a URL, gated by the `OpenUrl` device permission. **Don't
pass your own page's URL.** An honoured navigation to it reloads the product, which the 09:25 run on
2026-09-19 mistook for a bug until the probe was read. At 10:05, given an outside URL (a GitHub
page), the host **accepted the call in 28 ms, and the product kept running.** Whether the URL opened
in the system browser wasn't recorded.

## Theme

`getThemeProvider().subscribeTheme(cb)` delivers the current theme at once and then any changes.
**It follows the host's theme, not the phone's.** almanac saw the host dark (`berlinNight`) while the
phone was set to light (almanac P12). Style against the host theme.

## Chat

`getChatManager().subscribeChatList(cb)` is reachable, and 0 rooms were visible to a new product.
`registerRoom` and `registerBot` create lasting state on the host side and have not been probed.
