# Gas and signing

**Status (2026-09-19, codec 1, Android): AutoSigning is not available, so every host signature is a
tap. The contract-gas allowance answers `Allocated`, but nothing is minted until the account
transacts.** The findings below come from sonde runs at 15:43 and about 16:00, and from Paseo
Asset Hub and Asset Hub Next blocks read the same day.

## PGAS, the testnet gas asset

- **PGAS is asset `2000000000` in the `Assets` pallet** on Paseo Asset Hub and Paseo Asset Hub
  Next. Polkadot and Kusama Asset Hub have no PGAS pallet, so it is a testnet-only rail.
- **It is minted by `Pgas.claim_pgas(slot_index, target)`, an unsigned call.** The `AsPgas`
  transaction extension checks a ring-VRF personhood proof over the call, so the chain learns
  "some person claimed", not which one, and `target` can be any account.
- **Fees can be paid in it.** The `PgasAllowance` pallet emits `PGASFeePaid { who, actual_fee }`
  when a transaction's fee is taken in PGAS and burned.
- The asset has no metadata, but amounts show it has 10 decimals. A claim mints **5 PGAS**
  (`50000000000` raw). Fees seen on Asset Hub Next were 0.001–0.0065 PGAS a transaction, so one
  claim covers roughly 750–4,500 transactions.
- **Seen on Asset Hub Next, 2026-09-19:** each `PgasClaimed` was followed, within 15 blocks, by the
  target's first transactions, each paying its fee in PGAS. That fits a host that claims lazily, on
  the first submission.

```ts
// Storage key for an account's PGAS: Assets.Account(2000000000, accountId)
const PREFIX =
  "0x682a59d51ab9e48a8c8cc418ff9708d2b99d880ec681799c0cf30e8886371da946de6e688c2258c9eb90a9b5c834b13d00943577";
const key = PREFIX + hex(blake2b(accountId, { dkLen: 16 })) + hex(accountId);
// state_getStorage(key) → AssetAccount; the balance is the first 16 bytes, little-endian.
```

## The host's allowance

`requestResourceAllocation([{ tag: "SmartContractAllowance", value: index }])` is described in
truapi as a "pre-warmed PGAS balance for the product account at this derivation index". The host
may also grant it implicitly on the first transaction. Only the host can make the ring-VRF proof,
so a Product can't claim PGAS for itself; it gets PGAS through this call, to a product account
the host picks by index.

**Measured (2026-09-19):** the host answered `["Allocated"]` after 11.4 s, which suggests a
prompt. But no PGAS reached product account #5 on either Asset Hub in the 36 minutes after, and
no claim anywhere targeted it. **Expect the PGAS to arrive with your first transaction, not
before.** A balance check right after `Allocated` will read zero.

**Measured with a transaction (2026-09-19, host.gas.firstTransaction):** product account #5, holding
nothing, sent one host-signed `System.remark` to each hub, with `AsPgas` set to `None`.

- **Paseo Asset Hub:** the host signed with no allowance step, and the chain refused it
  `Invalid: Payment`. The host adds no PGAS there.
- **Paseo Asset Hub Next:** the host showed an "allocate resources" step, then "fails to load
  transaction", and the call ended `createTransaction failed: User rejected` after about 4 s. No
  `PgasClaimed` landed on Next during either attempt, for this account or any other.
- **How working products do it on Next:** a separate 851-byte general (v5) extrinsic carries
  `claim_pgas` with the ring-VRF proof. The target's normal signed transactions follow, fees paid in
  PGAS. Every claim seen names `collection: LitePeople`. So the user has to be in the People Lite
  ring for the host to claim. **Confirmed as the likely cause:** the tester's account was rank
  "basic", with no personhood, so the host had no proof to make.

- **Pass the index as a tagged union.** `value` is a `DerivationIndex`:
  `{ tag: "Index", value: 5 }` (or `{ tag: "Raw", value: <32 bytes> }`). A bare number throws
  `t[o] is not a function` inside the SDK before anything reaches the host.
- **Don't use it to fund a private account.** Product accounts derive from the user's root public
  key, so anyone who knows that key can link them.

## AutoSigning

`AutoSigning` is also a `requestResourceAllocation` tag. **Measured 2026-09-19 on Android: the host
answers `["NotAvailable"]`** (in 956 ms), and the signature after it took 9.7 s, which was a tap.
`product-sdk-terminal`'s types say the same for iOS. So every host-signed transaction is a tap, and
nothing host-signed can run in the background. Work that must happen without the user signs with
an app-local key (seed it from `deriveEntropy`) and pays its own gas.
