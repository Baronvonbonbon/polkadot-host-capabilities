# Identity, accounts and signing

**Status (2026-09-19, codec 1, Android):** connect, product accounts, deterministic entropy and
host signing all work. The Ring VRF anonymous alias returns `null`. WebAuthn is absent.

## Accounts a Product sees

- **Product accounts** derive from the user's root *public* key, the product id and an index:
  `deriveProductAccountPublicKey(parentPublicKey, productId, index)` in `product-sdk-keys`. Indices
  give distinct keys (0, 1, 2 and 7 were checked). The catch: **anyone who knows a user's root
  account can compute all their product accounts.** Per-index accounts do not hide a user from
  someone who knows the root.
- **The app often shows a Product only product account #0**, so there is no root to derive from
  inside the app (almanac P8).
- **Different jobs are signed by different accounts.** Uploads through `cloudStorage` are signed by
  product account #0. Statements are signed by the allowance account, which is none of #0–#2.
  Bulletin preimages are paid by a hidden slot account (almanac P6b, P8).
- `getUserId()` returns a stable per-user handle. `getLegacyAccounts()` returned 0 accounts.

```ts
import { createApp } from "@parity/product-sdk";
const app = await createApp({ name: PRODUCT_ID, cloudStorage: { environment: "devnet" } });
const r = await app.wallet.connect();
app.wallet.selectAccount(r.accounts[0].address);   // connected but unselected: storage calls stall, not error
```

## Keys a Product can keep for itself

`deriveEntropy(input)` is **deterministic per product**. It gives the same bytes for the same input,
across app restarts and across new builds of the product (almanac P2). Seed an app-local key with it
and the key regenerates from nothing. Reinstall and a second phone are not measured yet.

**EVM signatures:** the host signs sr25519. A contract's `ecrecover` needs secp256k1. An app-local
secp256k1 key signs EIP-712 in 2–3 ms, and `verifyTypedData` recovers it exactly (FARE and sonde).
So attestations a contract checks are signed locally, and the host signs chain transactions.

## Signing through the host

`app.wallet.signMessage` shows the host's prompt and returns 64 bytes. AutoSigning reports
`NotAvailable`, so every signature is a tap. The promise settles only when the user answers.

## Publishing is a different story

`pad`, the deploy tool, signs through the phone as a hidden product account. The app never reveals
that account, and it changed between app releases. So a `.dot` name registered from the phone can
end up owned by an account the phone no longer signs as. Publish with a local deploy key:
[pitfalls/deploy-with-a-key.md](../pitfalls/deploy-with-a-key.md).
