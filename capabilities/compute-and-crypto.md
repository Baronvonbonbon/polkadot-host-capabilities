# Compute, crypto and workers

**Status (2026-09-19, codec 1, Android): fast and complete for a single thread.** There is no
`SharedArrayBuffer`, because the page is not cross-origin isolated, so there are no WASM threads.

- **WebAssembly** compiles and runs, with SIMD available, so crypto libraries take their fast path.
- **`crypto.subtle`** supports every algorithm tested, **including Ed25519 and X25519**.
- **Dedicated Workers** work, including one started from a blob URL. SharedWorker is absent.
- **`SharedArrayBuffer` is not defined** (`crossOriginIsolated` is false). Multi-threaded WASM
  builds (some zk provers, some argon2/scrypt builds) must fall back to single-threaded.
- **Timer resolution:** `performance.now()` ticks at 0.1 ms.

## Real numbers on a phone (Pixel 10 Pro XL, almanac P11)

| Work | Time |
|---|---|
| scrypt r=8, N=2¹⁵ | 101 ms |
| scrypt r=8, N=2¹⁶ | 169 ms |
| scrypt r=8, N=2¹⁷ | 328 ms |
| XChaCha20-Poly1305, 1 MiB | 24 ms encrypt, 8 ms decrypt |
| BLAKE2b-256, 1 MiB | 18 ms |
| AES-256-GCM, 3.2 KiB (FARE) | 1 ms |
| secp256k1 EIP-712 sign + recover (FARE, sonde) | 2–3 ms |

This is a flagship phone; expect roughly 2–3× slower on mid-range hardware. FARE also runs a real
Groth16 proof for delivery proximity. Its proving time on a phone isn't in this repository yet.
