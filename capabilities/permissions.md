# Permissions

A Product deals with **two permission systems that don't talk to each other**:

1. **Host permissions.** These are truapi's `requestDevicePermission(name)` and `requestPermission(…)`.
   The Polkadot app shows its own prompt and returns a `Result<boolean>`.
2. **Web permissions.** These are the Android WebView's, for geolocation, camera, clipboard and so
   on. The host has to answer the WebView's callbacks for them.

A host grant doesn't imply the web API works. Location is the proof: the host grants it and
`navigator.geolocation` still fails ([location.md](location.md)). Camera and microphone do work
through `getUserMedia` ([media-and-calls.md](media-and-calls.md)).

## Device permissions

`requestDevicePermission` takes one of: `Location`, `Camera`, `Microphone`, `Notifications`,
`Bluetooth`, `NFC`, `Clipboard`, `OpenUrl`, `Biometrics`. All nine were granted on 2026-09-19. The
grant is what the host says; whether the matching web API then works is a separate row in the
matrix.

```ts
import { requestDevicePermission, formatHostError } from "@parity/product-sdk-host";
const r = await requestDevicePermission("Camera");
if (!r.ok) console.warn(formatHostError(r.error));    // @parity/result: read r.ok, never r.isOk()
else if (!r.value) console.warn("declined");
```

## Remote and resource permissions

- **`requestPermission({ tag, value })`** covers what a Product may ask the host to *do*. There
  are five variants, and all five were granted on 2026-09-19:
  - `Remote`, with `{ domains: [...] }`, for outbound network access
  - `WebRtc`
  - `ChainSubmit`
  - `PreimageSubmit`, for storing on Bulletin ([bulletin-storage.md](bulletin-storage.md))
  - `StatementSubmit`

  The submit variants are also asked for implicitly by the calls that need them. So a refusal here
  can surface later as a failure that looks unrelated.
- **`requestResourceAllocation([{ tag }])`** covers quota: `BulletinAllowance` and
  `StatementStoreAllowance`. It returns an outcome per item. `Allocated` is not the final word:
  Bulletin's allocation lands on a slot account that only the host can use.

## Web permissions that are blocked by the embedder

The app's WebView disables these for the document. The Permissions-Policy or a WebView setting
refuses them before any prompt:

- fullscreen
- Picture-in-Picture
- clipboard **read** (clipboard write works)
- Idle Detection
- Web NFC scan
- WebGPU (no adapter)

See [ui-and-display.md](ui-and-display.md) and [sensors-and-hardware.md](sensors-and-hardware.md).
