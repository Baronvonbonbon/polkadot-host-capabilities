# Location

**Status (2026-09-19, codec 1, Android 16): not available to a Product.** The host grants its
`Location` permission, and `navigator.geolocation` still fails straight away. Design for no GPS.

## What happens

An Android WebView only gets location if the host app holds the OS permission **and** answers the
WebView's `onGeolocationPermissionsShowPrompt` callback. The Polkadot app does neither for a Product:

```
navigator.geolocation.getCurrentPosition → error code 1, "User denied Geolocation"
permissions.query({name:"geolocation"})  → "prompt"   (before and after)
```

`prompt` means the permission was never decided: no dialog was shown and nothing was stored. A real
refusal by the user leaves `denied`. So the pattern **denied with the state still `prompt`** means the
host never answered the callback. sonde calls this `host-callback-missing`.

truapi declares `requestDevicePermission("Location")`, and the host grants it. Even with Android's
own location permission allowed for the app as well (2026-09-19 10:38), nothing changes. Measured 2026-09-19,
granting it changes nothing: web geolocation run straight after still fails the same way. The two
permission systems are not connected. Upstream:
[products-devnet-issues#7](https://github.com/Polkadot-Community-Foundation/products-devnet-issues/issues/7).

## What to do

1. **Ask the host anyway, once a session.** It costs one prompt, and a fixed app build may start
   honouring it.
2. **Classify the failure.** Don't tell the user "you denied location" when they never saw a prompt.
3. **Build a path that needs no GPS.** Something a person can do: scan a QR code, confirm a pin on a
   map, or have the other party co-sign.

```ts
import { isInsideContainer, requestDevicePermission, formatHostError } from "@parity/product-sdk-host";

// Host calls can hang rather than fail — give each one a deadline (pitfalls/host-calls-can-hang.md).
const inHost = await Promise.race([isInsideContainer(), new Promise<boolean>((r) => setTimeout(() => r(false), 1500))]);
if (inHost) {
  const r = await requestDevicePermission("Location"); // Result<boolean> from @parity/result: check r.ok
  if (!r.ok) console.warn(formatHostError(r.error));
}

async function position(): Promise<GeolocationPosition> {
  const before = (await navigator.permissions?.query({ name: "geolocation" }))?.state;
  return new Promise((resolve, reject) =>
    navigator.geolocation.getCurrentPosition(resolve, async (e) => {
      const after = (await navigator.permissions?.query({ name: "geolocation" }))?.state;
      // Denied without the state ever leaving "prompt": the host never answered the WebView.
      const hostGap = e.code === e.PERMISSION_DENIED && before === "prompt" && after === "prompt";
      reject(Object.assign(new Error(e.message), { kind: hostGap ? "host-callback-missing" : "user-or-os" }));
    }, { enableHighAccuracy: true, timeout: 15_000 }),
  );
}
```

### A design that settles without GPS

FARE, a delivery product, settles on **two parties who can't both lie signing the same place**. It
doesn't trust either phone's GPS:

- **Pickup:** the driver signs the venue's published pin, not their own fix.
- **Dropoff:** the customer builds the driver's commitment from the drop position and a fresh salt,
  and shows it as a QR code. The driver scans it and signs it blind. The zero-knowledge proximity
  circuit is unchanged, because it only ever needed coordinates both parties committed to.

The source is in the FARE repository (`web/src/handoff.ts`), and there is a summary in
[sources/fare.md](../sources/fare.md).

  the Polkadot app, and the Polkadot app lists Location as granted to the product. Web geolocation
  was **still refused, in 3 ms, with the state at `prompt`**. The OS and the host have both said
  yes, so what's left is the app's WebView. A refusal that fast means no prompt was ever raised:
  the app doesn't grant the WebView's geolocation request (`onGeolocationPermissionsShowPrompt`'s
  callback), or has geolocation turned off in its WebView settings.
